You send an important message. It never arrives.

TeamChat is a messaging app for people and teams. HarborCloud is its cloud platform. Fixing the failure needs both teams.

But their logs can contain customer information and private system details. Engineers must pick out what is safe to share, pass findings back and forth, and check whether each fix actually restored delivery.

Relay connects their agents through Switch. Each investigates its own systems. Only owner-approved findings reach the other team. Each company approves changes to its own systems.

Then both teams test what customers care about: did the messages arrive?

Here’s how.

Maya reports the problem in the shared Mattermost incident channel. Leo, HarborCloud’s engineer, confirms his team is available.

TeamChat’s agent checks its own service. It finds connection failures and message servers that failed to start.

Its detailed diagnostic observations stay in TeamChat’s context. The agent prepares a short incident finding and a focused question for HarborCloud.

Maya reviews that finding, including the highlighted question, and replies, “Share with HarborCloud.”

The exact approved text arrives in the shared incident thread through Switch. HarborCloud’s agent receives it and investigates its own connection.

It finds the overload and proposes more capacity. Leo reviews the change in his private workroom and replies, “Approve this change.”

HarborCloud’s connection is healthy. But customers’ messages are still failing. Relay carries that result back to TeamChat’s agent, which investigates what remains.

It proposes recovering the failed parts of TeamChat’s message service. Maya reviews and approves the change.

The agent performs the recovery. Its reviewed result returns to the incident thread.

Run the same delivery test again: 24 messages sent, 24 arrived.

Maya asks the agent to retry an earlier message that genuinely failed. The same message arrives. A repeated request does not create a second copy.

Both teams controlled what was shared and changed. The incident thread records their findings, approvals, and results: 24 messages delivered, and the earlier failed message recovered.

Relay. Two teams. One recovery.
